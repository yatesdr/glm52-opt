# GLM-5.2 r17 / TR3-3.36 production candidate

This image derives from immutable Gilded Gnosis v20 r17 and adds only the
qualified CN4 changes:

1. four-rank `i8_hier` transport on SparkInfer #105's PCIe lifecycle;
2. bounded, one-grid mixed-K3/K4 EXL3 prefill planning;
3. deterministic paired-M8 FC2 execution that restores reference KLD.

Image tag:

`ghcr.io/yatesdr/glm52-serve:gilded-gnosis-v20-r17-tr3-336-i8hier-pairedfc2-20260801`

Immutable image:

Exact rebuild context:

## Start the long-context profile

```bash
mkdir -p hf-cache cache
docker compose \
  -f compose/glm52-v20-r17-tr3-336-i8hier-onegrid-shareable-20260801.yaml \
  up -d
```

The default profile is TP4/DCP4/MTP0, 480k maximum model length, dynamic
NVFP4 MLA KV, FP8 RoPE, exact sparse selection, and prefix caching. It
allocated 609,024 GPU KV tokens on CN4.

## Start the C16 throughput profile

```bash
MTP=3 MAX_NUM_SEQS=16 GRAPH=64 TRELLIS_MAX_M=64 MAX_MODEL_LEN=100000 \
docker compose \
  -f compose/glm52-v20-r17-tr3-336-i8hier-onegrid-shareable-20260801.yaml \
  up -d
```

The shorter maximum length is intentional: the graph-64 MTP3/C16 profile
retains more graph memory than the MTP0 long-context profile. CN4 measured
234.05 aggregate tok/s with 16/16 requests active and zero errors.

## Topology boundary

`i8_hier` requires exactly four ranks arranged as two fast pairs. The default
CN4 configuration uses `NCCL_P2P_LEVEL=PXB`. On another topology, override
`F8_DMA=i8_ring` and choose the appropriate NCCL P2P level rather than assuming
the CN4 schedule is optimal.
